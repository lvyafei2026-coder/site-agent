| 阶段 | 目标 | 状态 | 验收标准 |

| 0 · 基建 | 凭据、建表、部署、最小链路跑通 | **进行中**（文档与骨架已完成，凭据未接） | 手动触发 `daily-report` 能收到邮件 |

## 3. 阶段 1 · 数据日报（第 1 周）

**为什么先做这个**：纯读、零风险、立刻有用。它验证了"能不能连上 D1 / GSC / 邮件"这条最基础的链路，而这些链路是后面所有功能的前提。

### 待办

- [ ] `SQL_DAILY` 校准（按天 / 站 / 页三维聚合）
- [ ] GSC 拉取 28 天展示、点击、CTR、排名
- [ ] LLM 解读 prompt 调到"能说出具体结论"而不是"总体表现良好"
- [ ] HTML 邮件模板（含成本行：本日 token / 累计花费）
- [ ] `agent_reports` 落库（`UNIQUE(report_date, kind)`）
- [ ] GSC 表现回填 `agent_pages`（clicks / impressions / position）

### 验收

连续 3 天的日报满足：

1. 能指出**具体**的异常（"paypal 站 `/paypal-fee-for-freelancers.html` 展示 320 次、点击 2 次，CTR 0.6%，标题需要重写"），而不是泛泛而谈
2. 每条建议都能对应到一个具体页面或站点
3. 数据与 GSC 后台手工核对一致

### 调 prompt 的经验

- **在 prompt 里给定阈值**："CTR < 1% 且展示 > 100 → 标题问题；排名 11-20 且有展示 → 值得加内容"——不给阈值，模型会输出"表现良好"
- **要求引用数字**：每条结论必须带具体数值，否则丢弃
- **限制条数**：actions 最多 5 条，多了人会不看

## 4. 阶段 2 · 内容页闭环（第 2 周）

**这是全链路价值最高的一环**，也是 radar 一直缺的那块拼图。

### 待办

- [ ] radar 候选词接口联调（`status=doing` 过滤）
- [ ] `config.SITES` 补齐要接入的站（当前只有 5 个 AI 站）
- [ ] 模板 `templates/site-page.html` 按目标站的实际样式调整
- [ ] `DEAD_PATTERNS` 与 radar 的 `DEAD_RULES` 对齐
- [ ] prompt 里注入"站内已有页面 URL"防重复 + "SERP top10 标题"做参考
- [ ] git 部署链路实测（check run 轮询、空提交重推、线上 200 校验）
- [ ] GSC Indexing API 提交（配额 200/天，注意别超）
- [ ] sitemap 更新逻辑按实际 sitemap 结构校验
- [ ] **前 20 页人工全看**，建立质量基线

### 验收

- 全自动上线 ≥5 个页面，全部线上 200 且标题正确
- 7 天内 GSC 收录 ≥2 个
- 无一页触发 DEAD 规则或重复建页
- 人工抽查质量可接受（读得通、有信息量、不是模板套话）

### 这一阶段最容易翻车的地方

1. **模板套不上目标站**：`site-page.html` 是通用骨架，直接推到有自己设计系统的站会显得突兀。前几页应该是"和该站现有页面长得一样"，而不是"新模板"。
2. **内容像 AI 写的**：prompt 里要给"具体数字、具体场景、具体反例"，禁止"总之""值得注意的是"这类填充。这条决定收录质量。
3. **一次上太多**：新站首月 ≤3 页/天。内容突增是明显的算法信号。

- [ ] 周排期生成 prompt（渠道 × 日期 × 素材草稿）

- [ ] `agent_reports (kind='plan')` 落库与读取
- [ ] 每日 09:00 提醒当日任务（合并进日报邮件）

### 验收

- 生成下周排期，**每一条都通过校验器**
- 单测覆盖所有红线，故意构造违规条目能被拦下
- 排期内容与最近上线的页面相关（不是凭空排的）

### 红线清单（代码里的，不是文档里的）

| 渠道 | 规则 | 校验方式 |
|---|---|---|
| X | 主推不含任何外链 | 正则 `https?://` 命中即拒 |
| Reddit | 新号不贴链接 | 缺 `approved_account` 标记即拒 |
| YouTube | 同一音轨不批量复用 | 需人工确认（暂未自动校验） |
| 全渠道 | 同渠道同一天最多一条主推 | `(date, channel)` 去重 |
| 全渠道 | 文案 ≥40 字符、必须有标题 | 长度与字段校验 |

## 9. 两条不做的事（写进路线图，避免以后被自己推翻）

1. **不做全自动发帖**。Reddit / HN / X 的账号是养号资产，一次批量操作就可能全废。Agent 只准备草稿，人点发送。
2. **不做外链群发**。搜索引擎对批量外链的判定非常成熟，收益远小于风险。

这两条不是"暂时不做"，是**设计边界**。要改的话，先改 [02-architecture.md 的 ADR-6](02-architecture.md#adr-6-红线写进代码而不是-prompt)。
